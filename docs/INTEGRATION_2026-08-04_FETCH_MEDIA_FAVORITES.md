## 2. 本次改动解决的问题

### 2.1 全局抓取调度

- 将抓取间隔从逐来源配置改为全局策略，保存于 `app_settings.global_fetch_interval_minutes`。
- 新增、批量导入、重新启用来源，以及修改全局间隔时，均在未来 1–5 分钟内随机错峰排期。
- 每个来源成功或失败后，都以“全局间隔 + 1–5 分钟随机延后”安排下一次抓取；相邻请求再随机等待 2–5 秒。
- 来源管理页显示上次检查、新增条数和下次抓取时间；设置页可修改统一间隔。
- Docker Worker 拆为 `collector` 与 `processor`：前者快速检查到期来源，后者处理摘要、筛选、翻译、简报和清理，避免模型调用拖慢排期检查。

### 2.2 媒体预览

- `items.media_json` 持久化图片、视频和受信任嵌入信息；同一 GUID 的再次抓取会回填媒体，不会重复触发摘要和筛选。
- RSS/Atom、HTML、YouTube、B 站和 X 抓取路径均提取媒体；只接受 HTTP(S) 直链和明确白名单的平台嵌入地址。
- 详情页展示图片、视频播放器或嵌入播放器；加载失败时仍提供原始媒体链接。

### 2.3 收藏与内容保留

- 复用 `feedback.action = saved`，不额外引入一张状态表。
- 首页、详情页和收藏页都可收藏或取消收藏；收藏详情在来源暂停、归档后仍可访问。
- 每次 `processor` 处理完成后清理超过 30 天的普通内容；收藏事件及其条目、仍被保留日报引用的事件及其条目不会删除。
- 遇到保留期内日报引用 JSON 损坏时，清理逻辑宁可多保留旧事件，也不冒险误删。

### 2.4 最近 5 天显式反馈

- 每次项目级筛选都会读取最近 5 天的 `read`（用户展开摘要或主动进入详情）和 `not_interested`（用户点击“不感兴趣”）行为。
- 只有 `feedback.action = 'not_interested'` 才是负向反馈；Skill 自动判定为 `hidden` 的内容不会被当作用户偏好。
- 传给 Skill 的反馈字段仅有动作、操作时间、事件标题和摘要，不包含原始正文、来源账号、链接或点击次数。
- `read` 是弱正向信号，`not_interested` 是明确但不可泛化的负向信号；二者只影响四层判断和同层排序，绝不参与事件合并、去重或拆分。

## 3. 核心调用链

```text
设置页保存全局间隔
  -> Repository.save_fetch_policy
  -> app_settings 持久化 + 启用来源随机重排

collector Worker
  -> Repository.schedule_unplanned_sources / due_sources
  -> 插件抓取（相邻请求随机等待）
  -> insert_item（含 media_json）
  -> schedule_next_fetch

processor Worker
  -> 摘要 / Skill 筛选 / 翻译 / 简报
  -> purge_expired_content（保护收藏和日报引用）

热点页或详情页收藏
  -> Web 路由
  -> Repository.save_event / unsave_event
  -> 收藏页或原页面重定向

用户展开摘要、主动进入详情或点击“不感兴趣”
  -> feedback（read / not_interested）
  -> Repository.list_recent_explicit_feedback
  -> CurationService.recent_feedback
  -> 项目 Skill 的层级判断与同层排序
```

## 5. 遇到的问题与处理

| 问题 | 原因 | 处理 |
| --- | --- | --- |
| 不能直接合并三个功能分支 | 三个分支落后于当前主线，直接合并会覆盖来源备份、表单精简及最新的结构维护决策 | 以最新 `main` 新建工作树，按模块移植并保留主线改动 |
| 最新主线已移除 v6 → v7 的一次性迁移工具 | 本次功能仍需新增 v8 字段，直接沿用固定 v7 会使已有线上数据库无法启动 | 经用户明确授权，恢复 v7 → v8 的只读预检、备份和单事务迁移；运行时仍拒绝自动改表 |
| 来源备份测试仍期待逐来源间隔恢复 | 全局调度下该字段只为旧数据兼容保留，不应影响新调度 | 导出不再写入该字段，恢复后采用数据库全局策略，并更新测试与说明 |
| 收藏详情在来源停用后会查不到内容 | 常规查询刻意隐藏停用来源 | 收藏详情在确认收藏状态后使用包含停用来源的读取路径 |
| 清理过期内容可能破坏日报阅读 | 日报只保存事件 ID，直接删旧事件会留下失效引用 | 先删除过期日报，再解析剩余日报引用；解析异常时停止事件清理 |
| 隐藏页混有系统隐藏和用户“不感兴趣” | 将所有隐藏内容当作负反馈会把模型历史判断误认为用户偏好 | 只查询用户显式写入的 `feedback.action = 'read' / 'not_interested'`，不读取 `hidden` 层级 |

## 6. 失败处理与已知代价

- 单个来源抓取失败仍会写入错误状态并进入下一轮排期，不会无限立即重试，也不会中断其他平台。
- 媒体只保存远端 URL，不下载或代理媒体文件；第三方媒体源不可用时，预览可能加载失败，但原始链接仍可打开。
- YAML 来源快照不包含全局抓取策略。这个取舍避免向正在运行的实例导入来源时覆盖其负载设置，代价是新环境恢复后需手动设置抓取间隔。
- 旧数据库必须先停止 Web/Worker，再通过 `migrate --check` 和 `migrate --apply` 升级到 v8；应用运行时不会自动改表。
- 近期反馈在下一次筛选运行时才生效，不会即时重排已展示卡片；最多传入 60 条，且优先保留用户显式“不感兴趣”。
- 后续筛选若将两个已有事件重新合并，当前实现不会同步替换日报 `event_ids_json` 中被删除的冗余事件 ID；日报可能因此少一条内容。该风险已复现并经用户确认暂不处理。
